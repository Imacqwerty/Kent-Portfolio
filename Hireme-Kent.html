How I troubleshoot

My step-by-step approach for Tier 1-2 incidents, from first report to closed ticket.

Illustrative example: User cannot connect to a server program
(Server IP = 192.168.10.1 | User IP = 192.168.10.95)
NOTE: Server Unit is up. Network Infrastructure has no DHCP Server. 

Symptom: "Log on failed or server application cannot be accessed" on user Desktop | 192.168.10.95
1. Cable and link lights OK, other terminals work → isolated to one unit
2. ipconfig /all → 169.254.x.x (no DHCP lease)
3. Borrow a valid IP that can connect to server (192.168.10.101)
4. ping the 10.95 IP if it is attached to a unit
5. If it's attached notify the user for a slight maintenance or if it's not then set the Desktop in it's own IP
6. Let the user try it. If the user is satisfied, close the ticket and document it afterwards for future reference

Different approach will be applied if it has DHCP Server


  1. Understand the issue. Who is affected, what they were doing, the exact error message, when it started and what changed. I log it in the ticket right away.
  2. Assess priority. One user or the whole counter? Is it blocking sales? I set priority and severity based on impact and the SLA.
  3. Check the basics first. Power, cables, link lights, peripherals and user login. Many issues end here.
  4. Isolate the layer. Hardware, operating system, network, then application, changing one thing at a time. Tools: Event Viewer, Reliability Monitor, services.msc, ipconfig, ping, tracert, nslookup, sfc, DISM, chkdsk and bootrec.
  5. Fix and confirm. Apply the fix, test it, and confirm with the user that it is truly solved before closing.
  6. Document or escalate. Record symptoms, steps and result in the ticket and knowledge base. If it is beyond my scope or the SLA is at risk, I escalate to senior IT with everything already tried.
